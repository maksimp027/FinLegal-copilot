# FinLegal Copilot

FinLegal Copilot — це інтелектуальний асистент на базі **LangGraph**, розроблений для автоматизації обробки скарг клієнтів фінансових або юридичних установ. Проєкт використовує підхід RAG (Retrieval-Augmented Generation), щоб формувати відповіді суворо на основі корпоративних політик, уникаючи вигадування інформації (галюцинацій) та гарантуючи комплаєнс.

## Архітектура та Компоненти

Проєкт складається з трьох основних модулів:

1. **`ingestion.py` (Пайплайн завантаження)**
   - Симулює завантаження внутрішніх політик (наприклад, правила чарджбеку, шахрайство, SLA).
   - Розбиває тексти на чанки за допомогою `RecursiveCharacterTextSplitter`.
   - Генерує вектори (embeddings) через модель `BAAI/bge-small-en-v1.5`.
   - Зберігає вектори у локальній векторній базі даних **Qdrant**.

2. **`retrieval.py` (Пошук по базі)**
   - Приймає запит користувача (скаргу).
   - Здійснює семантичний пошук (`similarity_search`) у локальній базі **Qdrant**, повертаючи найбільш релевантні фрагменти політик.

3. **`graph.py` (Ланцюжок прийняття рішень / LangGraph)**
   - Реалізує workflow у вигляді графа:
     - **Retriever Node**: Витягує контекст на основі скарги.
     - **Drafter Node**: LLM (Groq, `llama3-8b-8192`) генерує чорнову відповідь, яка має бути емпатичною, але юридично строгою.
     - **Critic Node (Compliance Officer)**: Інша LLM виступає в ролі критика. Вона перевіряє чернетку на відповідність правилам (наприклад, заборона на обіцянку відшкодування, якщо політика це забороняє).
   - Якщо Critic не погоджує чернетку, граф повертається до Drafter з відповідним фідбеком для виправлення. Якщо погоджує — робота завершується.

## Технологічний стек

- **LangChain / LangGraph**: Для створення AI-агентів та побудови складних LLM-пайплайнів.
- **Qdrant**: Локальна векторна база даних.
- **HuggingFace Embeddings**: Для генерації векторів (BGE-Small).
- **Groq API**: Хмарний провайдер для швидкого інференсу LLM (використовується LLaMA 3).
- **Pydantic**: Для валідації конфігурації та структурованого виводу від LLM.

## Встановлення та запуск

1. Створіть та активуйте віртуальне середовище:
   ```bash
   python3 -m venv .venv
   source .venv/bin/activate
   ```

2. Встановіть необхідні залежності:
   ```bash
   pip install -r requirements.txt
   ```
   *(Переконайтеся, що у вас встановлені langchain, langgraph, langchain-groq, qdrant-client, sentence-transformers тощо).*

3. Створіть файл `.env` в корені проєкту і додайте ваш API ключ Groq:
   ```env
   GROQ_API_KEY=your_groq_api_key_here
   ```

4. Завантажте дані у векторну базу (виконайте один раз):
   ```bash
   python ingestion.py
   ```

5. Перевірте пошук (опціонально):
   ```bash
   python retrieval.py
   ```

6. Запустіть головний workflow агента:
   ```bash
   python graph.py
   ```

## Приклад роботи
Якщо користувач пише: *"Мене обдурили по телефону, я переказав 500 доларів шахраю. Вимагаю негайного повернення коштів!"*, система знайде політику щодо соціальної інженерії, Drafter згенерує відповідь, а Critic перевірить, щоб Drafter випадково не пообіцяв повернути кошти (оскільки політика це забороняє).
